# 子待办设计

日期：2026-10-17
状态：待审核

## 1. 目标与约束

**目标**：一个待办下可以拆出若干小待办（子待办），在主面板展开行时直接查看、勾选、添加和整理。

**产品方向变更**：`AGENTS.md` 原约束「不要把描述做成子任务、清单……除非用户明确改变产品方向」。用户已明确要求支持子待办，本设计据此修改该约束；**描述内的 Markdown 清单仍不变成子任务**（PRD 5.1 原规则保留）。

**用户已确认的决策**

- 子待办在主面板**展开行时显示**；平时父待办行只显示进度「已完成/总数」。
- 父子完成状态**互不自动联动**。
- 子待办支持：添加、勾选、**重命名、删除（可撤销）、拖拽排序、提升为独立待办**。
- 编辑浮层中也显示同一子待办列表，**即点即存**；浮层的保存 / 放弃只作用于标题与描述。
- 数据方案：独立的 `SubtaskItem` 表，以 `parentID` 关联父待办。

**成功标准**

1. 在任一待办下连续添加 a、b、c、d，勾选、改名、排序、删除、提升都即时生效并在重启后保留。
2. 已有用户数据（事项、描述、附件、旧进度数据）在升级到含子待办的版本后完整保留。
3. 子待办永远不出现在象限列表、顶栏计数、已完成区计数中（它们只计父待办）。
4. 任一写入失败时界面回到原状态并提示，不丢已有数据。

**非目标**：多层嵌套；子待办的描述、象限、截止时间；父子完成联动；把普通待办降级为子待办；从描述清单解析子待办。

## 2. 数据模型

```swift
@Model
final class SubtaskItem {
    @Attribute(.unique) var id: UUID
    var parentID: UUID
    var title: String
    var isCompleted: Bool
    var completedAt: Date?
    var sortOrder: Int
    var createdAt: Date
    var updatedAt: Date
}
```

- 加入 `ModelContainer` 的 schema：`TaskItem.self, ProgressEntry.self, SubtaskItem.self`。新增实体属于 SwiftData 轻量迁移。
- `TaskItem` 不改字段。子待办没有象限，随父待办；父待办换象限 / 拖拽时子待办不需要任何改动。
- 一个父待办下子待办按 `sortOrder` 升序、`createdAt` 次序排列。新增追加到末尾（`max(sortOrder) + 1`）。
- 标题校验复用 `TaskTitle.validate`（去首尾空白、非空、≤ 200 字，粘贴换行转空格）。

**迁移安全**：`PersistenceController` 打不开库时会把库移成 `.broken-*` 并以内存库启动，迁移失败等于用户看到空应用。因此：

- 自动测试：用旧 schema（仅 `TaskItem`、`ProgressEntry`）在临时目录建库写入数据，关闭后用新 schema 打开，断言事项、描述、进度完整，且可写入子待办。
- 运行验证：以用户真实数据库的**副本**（`QT_DATA_DIR` 指向副本目录）启动新版本，确认事项完整；原库不触碰。

## 3. 规则

- **完成互不联动**：子待办全部完成只显示「4/4」；父待办只能通过自身圆圈完成。父待办完成后子待办保持各自状态，随父待办进入「已完成 N」区；在已完成区展开时子待办仍可操作。
- **进度**：父待办有子待办时，行尾箭头前显示 `已完成数/总数` 胶囊；全部完成时为浅绿色；无子待办不显示。悬停提示「子待办 1/4 已完成」。顶栏「N 个待办」与「已完成 N」只计父待办。
- **删除父待办**：其子待办一并删除；8 秒撤销恢复父待办及全部子待办（标题、状态、顺序）。撤销期结束后子待办不可恢复。
- **删除子待办**：进入现有撤销队列（8 秒，提示「已删除子待办「标题」 · 撤销」），撤销恢复到原位置与原状态。
- **提升为独立待办**：在父待办所属象限新建普通待办（标题、完成状态与完成时间保留；未完成则追加到该象限未完成列表末尾，已完成则进入已完成区），并从父待办移除该子待办。进入撤销队列：撤销删除新建的待办并把子待办放回原父待办原位置。
- **勾选子待办**：不弹提示。
- **描述**：Markdown 描述及 `- [ ]` 显示规则不变。

## 4. 界面交互

### 4.1 任务行

- 有子待办时显示进度胶囊；行尾箭头在「有描述或有子待办」时常显（原为仅有描述）。
- 单击行空白或箭头展开：先显示子待办区，再以分隔线隔开显示 Markdown 描述。只有子待办、无描述时不显示「暂无描述」；两者都没有时仍显示「暂无描述」与「+ 添加子待办…」。

### 4.2 子待办列表组件（展开区与编辑浮层共用）

- 每行：小完成圆圈 · 标题 · 悬停出现的拖拽把手与垃圾桶。已完成子待办标题为次要色并加删除线。
- 列表末尾常驻浅色输入行「+ 添加子待办…」：回车保存并追加、清空、保持焦点（便于连续输入）；Esc 清空；空白或超过 200 字显示提示且不创建。
- **事件优先级**（沿用 PRD 第 5 节原则）：
  1. 子待办圆圈：只切换该子待办完成状态。
  2. 子待办标题：单击原地变为输入框改名；回车或失焦保存，Esc 取消；空白或超长时提示并保持编辑。
  3. 垃圾桶：删除（可撤销）。
  4. 子待办区内任何点击都不冒泡为父行的展开 / 收起 / 编辑 / 拖拽。
- **排序**：拖拽把手只在同一父待办内重排，使用独立的拖拽类型，不能拖入象限、其他父待办或输入行。右键菜单提供「上移 / 下移」。
- **右键菜单**：上移、下移、提升为独立待办、删除。
- **自动收起**：子待办改名中或添加输入行有内容时，鼠标移出面板按「有输入」处理，不自动收起（与象限输入草稿一致）。

### 4.3 编辑浮层

- 在标题与描述编辑框之间显示同一子待办列表组件，即点即存。
- 「保存 / 放弃 / 未保存提醒」只覆盖标题与描述；列表上方小字说明「子待办修改会立即保存」。
- 浮层中的「删除」删除父待办时，子待办按 3 节规则一并删除并可撤销。

### 4.4 保存失败

- 所有子待办写入沿用现有 `persist` 失败保护：失败时回滚到写入前状态并以错误提示告知；`QT_FAIL_SAVES=1` 可模拟。改名失败时保持输入框和草稿；添加失败时保留输入内容。

## 5. 测试

**仓储单元测试**

- 添加（追加末尾、校验失败不创建）、改名、勾选 / 取消勾选（`completedAt` 设置与清除）。
- 删除与撤销（恢复原位置与状态）。
- 排序（上移 / 下移边界、拖拽到指定位置）。
- 提升与撤销（未完成追加到象限末尾；已完成进入已完成区；撤销放回原位并删除新待办）。
- 删除父待办连带删除子待办，撤销整体恢复。
- 父待办换象限后子待办仍关联。
- 进度计数；象限列表与计数不含子待办。
- `QT_FAIL_SAVES` 下各写入回滚。

**迁移测试**：旧 schema 建库 → 新 schema 打开，数据完整且可写子待办。

**运行验证**（截图存 `docs/verify/`）：进度胶囊；展开后的子待办区；连续添加 a–d；原地改名；拖拽排序；提升为独立待办；删除与撤销；编辑浮层子待办区；重启后保留；真实库副本打开完整。
